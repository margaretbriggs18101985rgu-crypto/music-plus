# 音频驱动的歌词与视觉设置

入口：播放器右上角或控制栏的「更多播放设置」→「歌词颜色与粒子特效」。在已有歌词、粒子数量等选项下方，展开「基础画面」「粒子与光影」「音域地形」「频谱响应」。参数独立保存，每个滑块右侧可恢复默认值。

**频谱柱默认隐藏。**「频谱响应 → 实时频谱」只控制频谱柱是否显示，关闭后仍然分析真实音频，以驱动歌词、电影镜头和已开启的音域地形。「音域地形」也默认关闭。

## 设置与实际作用

| 设置 | 实际作用 |
| --- | --- |
| 律动强度 | 调整音频对歌词强调、镜头推近、星流扩散和亮度的影响，0 为关闭这些节奏强调 |
| 画面景深 | 调整歌词透视距离、星流深度及投影焦距 |
| 封面清晰度 | 设置 Coil 封面解码目标尺寸 64–512，默认保留原来的 512；没有封面时显示原有占位 |
| 电影镜头及强度 | 真实鼓点触发镜头推近；检测到的节拍推进缓慢的双轴视角移动，频段平衡也影响视角 |
| 粒子溢光 | 在星点后绘制较大的低透明度光晕 |
| 歌词轮廓高亮 | 增加独立描边层，开启律动时由实际鼓点调节透明度 |
| 背景星河 | 控制星流显示，不会关闭歌词或独立的频谱、地形 |
| 粒子尺寸、运动速度 | 调整星点尺寸，以及星流和地形的视觉时间速度；速度变化不跳转动画时间 |
| 粒子扭曲、离散感 | 改变星流空间形态和分布范围，继续使用固定种子，不逐帧随机抖动 |
| 色彩张力、光晕强度 | 调整歌词、粒子和地形的颜色饱和程度，以及描边/粒子光晕；光晕为 0 时关闭对应光晕 |
| 背景压暗 | 压暗背景和装饰层，保留歌词及播放控件的对比度 |
| 音域地形及三个滑块 | 用真实的 32 段频谱绘制透视网格，控制振幅、纵深和垂直位置；颜色沿用歌词颜色 |
| 实时频谱 | 是否显示 32 段频谱柱，默认关闭 |
| Kick 自动频段 | 按低频瞬态在低频候选窗口间选择；关闭后使用手动 Hz 范围 |
| Kick 灵敏度 | 改变瞬态检测门限；越高越容易接受瞬态，也可能增加误触发 |
| 低、中、高频权重 | 分别影响歌词强调、镜头、星流亮度及地形/频谱对应频段 |

「歌词字体律动」控制歌词缩放强调；「歌词过渡与空间旋转」控制歌词过渡、手势和镜头；电影镜头可单独关闭。「动态背景」控制背景时间推进。总特效开关、系统减少动画及省电策略继续生效。播放暂停、失去有效音频或切歌时不会用固定周期补造鼓点。自定义壁纸继续替换背景星河，歌词镜头、频谱和地形仍使用同一音频分析。

## 实现与参考

对照 [Mineradio-paused](https://github.com/XxHuberrr/Mineradio-paused) 的提交 `d43de565acabfdc1a9c9820a27e81a98ccbebcef`，重点检查了：

- `public/js/modules/03-beat/01-audio-beat-analysis.js`：分频和瞬态分析。
- `public/js/modules/03-beat/06-sonic-audio-monitor.js`：频段、自适应窗口和鼓点响应。
- `public/js/modules/01-scene/02-beat-camera-runtime.js`：节奏与镜头分离。
- `public/js/modules/00-state/04-fx-defaults.js` 及歌词星河、主循环：参数类别、平滑包络和光影关系。

安卓实现独立编写，未引入该 GPL-3.0 项目的 Three.js/WebAudio 源码、运行时或素材。沿用本项目的 TrackPlayer/Media3 播放引擎、Compose、Coil 和设置存储，没有新增音频播放引擎、麦克风权限或逐帧 JS 通信。

`AudioBands.java` 分别计算左右声道 FFT 后合并功率，避免反相立体声在单声道求和时被抵消。Hann 窗随实际采样率选择大小，例如 48 kHz 时 2048 点，约每 20 ms 更新一次。输出 30 Hz–16 kHz 的 32 个对数频段、三段能量及低频瞬态。检测含自适应参考值、静音门限和最小触发间隔；切歌、Seek 和检测配置变化时重置历史。

`ReactiveAudio.java` 保留只读 PCM tap，并通过 Media3 的 `ForwardingAudioSink` 记录输入时间戳和实际 AudioTrack 输出位置，用有界队列选取已播放到的频谱帧。画面不会直接显示解码器提前读取的最后一帧。该路径使用 PCM16；无法获得有效 PCM 时不伪造频谱。视觉启用期间沿用已有的 offload 禁用/恢复机制。

歌词去掉原来的定时正弦缩放和直接低频位移。真实音频包络负责短促强调，较慢的跟随负责镜头移动，切句继续使用已有的淡入、纵向过渡和透视。

这是实时分析，不是整曲 BPM/节拍地图预分析。复杂编曲、低音人声及贝斯可能造成鼓点漏检或误判，可以调节灵敏度或手动频段；蓝牙和真机输出链路仍需单独观察同步感与功耗。

验证记录见 [2026-10-19 音频视觉验收](qa/2026-10-19-reactive-visuals.md)。
