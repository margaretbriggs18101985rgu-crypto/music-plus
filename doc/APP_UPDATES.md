# 应用内可选更新

MUSIC++ 在首次进入首页、从后台切回前台时检查更新；持续使用期间每 15 分钟再检查一次。成功检查限频 15 分钟，失败后 1 分钟可重试。自动检查失败不弹窗、不打断播放。同一个版本在同一次运行中只主动提醒一次。

发现新版本的弹窗按顺序提供三个选项：

- **取消**：关闭弹窗，继续使用当前版本，不下载、不安装。
- **更新**：下载 APK，显示进度，通过 SHA-256 校验后打开 Android 安装确认。没有安装权限时，由用户进入系统设置授权；拒绝授权或取消安装后，当前版本仍可继续使用。
- **不再提醒**：将本次版本号保存到本地，并关闭弹窗。重启后也不会主动提示这个版本；下一个新版本不受影响。

用户随时可以在 **设置 → 基本设置 → 软件更新 → 检查更新** 手动检查。手动检查绕过限频和已忽略版本，显示最新版本、当前版本、更新说明，或显示最新/失败结果。检查不会自动下载。

下载期间允许收起弹窗，手动检查会重新显示进度，不会重新检查或重复下载。若下载在后台完成，回到应用后显示安装按钮，由用户主动安装。关闭安装弹窗后，本次运行不会反复弹出。

## 版本来源与发布要求

1. 优先读取本仓库 GitHub Releases 的最新正式版本；仅接收 `vX.Y.Z`/`X.Y.Z` 版本标签，排除草稿和预发布，并要求五种 APK 和 `SHA256SUMS.txt` 均已上传。
2. GitHub API 暂时无法访问时，回退到 `main/publish/version.json`。必须按 [发布指南](RELEASING.md) 在云端资产验证完成后同步这份文件。
3. 每次正式发布都要递增 `package.json` 的 `version` 和 `versionCode`，保持应用 ID、签名密钥及现有 APK 架构的 versionCode 编码规则。无需额外的消息推送服务器。
4. 更新器根据当前安装包的实际 versionCode 选择相同架构；通用包仍更新为通用包。下载后核对同一 Release 的 SHA-256，再在原生层检查包名、签名和更高的 versionCode。
5. 当前版本由 Android 实际安装包提供，更新弹窗、设置页、版本比较及备份信息共用这一来源；不以可能缓存的 JavaScript `package.json` 版本判断是否已更新。

此功能需要包含这些代码的新 APK 才能生效；不能远程为已经安装的旧 APK 增加前台检查逻辑。此处的提醒是应用内检查，不是应用完全关闭时的系统通知。

## 实现参考与验证

沿用项目继承自 [LX Music Mobile](https://github.com/lyswhut/lx-music-mobile) 的更新弹窗、下载器和原生安装桥接，安装桥接原有参考为 [react-native-update-apk](https://github.com/mikehardy/react-native-update-apk)。继续使用现有文件下载依赖，没有额外引入一套更新 SDK。

`node --test tools/test-app-update.cjs` 覆盖版本提示、取消、逐版本忽略与重启、手动检查、生命周期和限频、并发请求、下载进度保持、后台完成、安装拒绝、五种架构、校验失败，以及版本来源回退。另运行 TypeScript、ESLint、全套 Node 测试和 Android 原生编译。
