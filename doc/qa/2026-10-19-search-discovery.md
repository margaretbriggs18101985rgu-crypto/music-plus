# 搜索、发现歌单与收听偏好修复

日期：2026-10-19。

## 结果

- 搜索首页移除原“歌曲 / 歌单”切换按钮，保留一个搜索框。提交关键词后同时检索 QQ 音乐、网易云的歌曲和歌单，并显示匹配歌手的主页入口，不依赖旧版保存的搜索类型。
- 结果提供综合匹配、热度优先、发布时间排序。歌曲继续使用原有 OnlineList 的播放、菜单、收藏等操作；歌单和歌手分别打开原详情页。
- 发现歌单刷新改为从最后展示过的源分页继续换批，后续加载保持连续，末页回绕。按平台、分类和排序独立保存位置，重启后继续；请求失败不推进游标，过期返回不覆盖新选择。
- 搜索首页的推荐歌单不再读取发现页的选源、分类、排序或换批游标。歌曲和歌单共用收听偏好、候选关键词与信号权重，同时保留探索位置和创作者多样性。
- 仅点击或零收听不进入偏好。旧记录的累计时长按播放次数分摊；新记录以每次播放实际覆盖的音频区间计算比例，重听同一片段不重复增加覆盖比例。

## 收听规则

已知歌曲时长时，平均覆盖至少 20%，且平均真实收听至少达到 `min(30 秒, 歌长的 20%)`，才形成正向偏好；未知歌长时至少需要平均 60 秒真实收听。这是本地推荐的可调整策略，不是对用户喜好的事实判断。

时间权重受有效收听比例的平方影响，重复收听权重有上限，并带时间衰减。数据不足时使用真实搜索结果作为探索内容。90% 的实际区间覆盖记为一次完成；暂停、缓冲和跳过的进度不计入覆盖。倍速同时考虑媒体进度和实际经过的时间。后台定时器严重延迟时保守舍弃异常样本，可能少计，不补造收听记录。

统计每 15 秒和暂停/停止等节点保存。进程被强杀可能丢失最后一个未保存采样区间。风格和语种根据现有文字元数据识别，并非对音频的分类模型。

## 排序边界

- 排序范围是已加载结果，加载更多后重新排序，不宣称对平台全库进行了全局排序。
- 热度保留网易云返回的歌曲 `pop` 与可用的 QQ 歌曲播放计数、两平台歌单播放次数。跨平台按当前候选集中各平台内部的相对热度比较；不把搜索位次冒充播放次数。缺失值置后，零值有效。
- 网易云歌曲搜索后批量补充详情中的热度和发行日期。选择发布时间时并发上限为 4，按需补充缺失日期并缓存；网易云回退使用官方专辑发行日期，QQ 使用歌曲详情的发行日期。没有可靠日期的项目置后。
- 歌单仅在接口实际返回创建日期时参与日期排序。不会用歌单更新日期、抓取日期或人为生成的日期冒充创建日期。歌手卡片保持平台顺序，不编造歌手的发行时间或热度。
- 部分平台请求失败时保留其他平台结果并提供重试；各平台分页独立，重试不会跳过失败页。

## 验证

- `npm run typecheck`、`npm run lint` 通过。
- `npm test`：148 项通过，覆盖换批、分页、末页回绕、失败重试、过期响应、重启游标、双平台混合搜索、热度归一化、缺失日期、日期缓存、零收听、多次短听、倍速、暂停/缓冲及拖到末尾。
- `npm run pack:android:debug`：四 ABI、内置 JS/Hermes 调试 APK 构建通过；安装于 `emulator-5554`。
- 模拟器搜索 `Drake` 返回 40 首歌曲、23 个歌单和匹配歌手入口；热度排序后出现网易云 251.2 万次与 QQ 344.5 万次的歌单，发布时间排序后的首批歌曲改变为 `Solar Eclipse`、`Janice STFU (Explicit)`。
- 点击歌单打开实际歌曲列表；点击歌手打开 Drake 主页，显示 2236 首歌曲、235 张专辑及热门歌曲。
- 发现页在同一平台、分类、排序下，下拉前首项为“重返2011”，下拉后为“下班听老歌”；持久化游标从第一页推进到第二页。
- 只读检查模拟器收听统计确认新增实际时长和覆盖比例字段已写入；本次采样记录为 35.893 秒、覆盖总比例约 0.1827，跨 2 次播放，不按一次完整播放处理。

截图、UI 层级、构建及测试日志在 `build/qa/songlist-refresh/`，该目录不提交。未把浏览器预览当作 Android 验收；长期真机推荐效果、不同网络下的接口稳定性及长期后台采样准确性仍需实际使用观察。
