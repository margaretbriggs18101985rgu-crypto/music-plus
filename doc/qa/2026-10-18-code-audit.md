# MUSIC++ 整体代码与功能入口审查

日期：2026-10-18。当前版本：1.1.2；本文记录本地工作区的审查与修改，尚未发布新 APK。

> 2026-10-19 后续修复：下文首次审查中标出的 75 个未引用文件及 5 组重复按钮已清理；歌词编辑、自动同步、设置／完整备份及桌面歌词未播放颜色入口已补全。当前结果与验证见 [功能补全与清理报告](2026-10-19-feature-completion.md)。下文保留首次审查时的候选和未完成状态，供追溯。

## 结论

已移除首次启动的协议签署、20 秒倒计时及旧品牌提示弹窗；首次进入首页直接启动更新检查和外部链接处理。已替换界面中的旧品牌文字，并恢复搜索页实际缺失的“歌曲／歌单”和“搜索平台”入口。

发现的主要问题是旧界面替换后残留的代码、没有入口的搜索能力，以及重复实现造成的事件清理错误。**静态扫描的未引用结果是候选清单，不等于这些文件都可以立即删除。**

## 范围与方法

- 从 `index.js → src/app.ts → 初始化与导航注册` 追踪 React Native 的静态和字面量动态导入，覆盖页面、状态、播放器、音乐源和工具模块。
- 使用开源 [Knip](https://github.com/webpro-nl/knip) 5.30.6 与 TypeScript 5.9.3 扫描，配置见 [knip.audit.json](../../tools/knip.audit.json)。额外用 TypeScript AST 对文件去注释后比较，查找整文件重复。
- 清点 Android 下 79 个 Java/Kotlin 源文件，核对注册、桥接和关键入口，并运行 Android 原生编译。检查发布工作流、构建配置与原生依赖，人工排除构建脚本、Metro 别名和协议兼容产生的误报。
- 本轮以静态入口审查和隔离运行测试为主，没有逐项在手机上点击所有功能，也没有重新验证所有第三方音乐平台的网络接口。iOS 仅同步显示名称，没有执行 iOS 构建。

完整候选清单与重复文件见 [机器可读结果](2026-10-18-code-audit-findings.json)。原始扫描、补充调用图及验证日志保存在本地 `build/code-audit/`。

## 已修复的问题

| 优先级 | 问题与依据 | 处理结果 |
| --- | --- | --- |

| P1 | `Home/Vertical/Main.tsx` 三处卸载函数调用了 `on('configUpdated', ...)`，导致重复添加监听 | 五套页面生命周期改用一个 `useLazyPage`；卸载完整移除四类监听，并取消未执行的动画帧 |
| P1 | 搜索后端和结果页支持歌单搜索，但 `SearchTypeSelector` 没有挂载 | 恢复“歌曲／歌单”选项，切换后保存设置并调用对应搜索结果页 |
| P1 | 搜索保存了平台选择且支持多平台后端，当前页却没有平台选择入口 | 复用现有 `SourceSelector`，只展示当前搜索类型支持的平台；切换类型时替换不支持的平台 |
| P2 | 歌单搜索命中缓存时没有刷新查询上下文，之后刷新可能仍使用旧平台 | `SonglistList.loadList` 开始时同步关键词和平台 |
| P2 | 搜索建议每次输入都创建独立延迟任务，关闭页面时没有取消；异步读取设置也可能晚于卸载返回 | 输入任务合并到一个定时器，取消旧任务；卸载时清理并阻止延迟初始化更新页面 |
| P2 | 设置合并函数有两套近似循环 | 合并为只遍历有效默认键的单个循环，未知／已退役的旧设置不再混入结果 |

## 无作用、重复与遗留代码

本次 Knip 扫描报告 **75 个未引用文件候选、136 个未使用导出候选、72 个类型候选**。整文件结构比较发现 **5 组重复文件**。这些数字是扫描结果，包含遗留界面和公共封装，不能直接相加当作真实缺陷数。

| 项目 | 判定 | 本轮处理 |
| --- | --- | --- |
| `Home/Views/Download/index.js` | 只有一个“下载”文字，占位页没有路由或导入；实际下载记录位于音乐库 | 删除占位页 |
| `Setting/settings/Backup/All.js` | 空文件，无调用 | 删除 |
| `list.isShowSource`、`list.isSaveScrollLocation` | 仅存在于默认值／类型／旧迁移，没有实际运行读取或控制入口 | 删除这两项无效配置及迁移 |
| `theme.lightId`、`theme.darkId` | 实际使用代码已被注释，当前自动主题使用 `common.isAutoTheme` 与 `theme.id` | 删除这两项无效配置及注释分支 |
| 旧横屏、竖屏播放页 | 当前播放路由统一进入原生 `Vertical/VinylPlayer`，旧 `Horizontal/index`、旧 `Vertical/Player`、旧歌词和图片组件未接入 | 在候选清单列出；保留作功能迁移参考，避免将旧歌词滚动等能力直接丢弃 |
| 旧评论页 | 当前 `Comment/index` 使用 `OfficialComments`，`LegacyComments` 及其旧列表未接入 | 列入可独立清理的旧实现候选 |
| 5 组相同按钮 | 旧横屏与竖屏分别保留相同的评论、桌面歌词、添加歌单、播放模式、定时退出按钮 | 重复位置全部列入 JSON；这些属于旧播放页，不是当前按钮重复渲染 |
| 旧百度源及 `musicSdk/*/temp` | 音乐源注册已排除百度，部分新旧试验模块无导入；其中试验文件还保留失效相对引用 | 标为未接入的旧源／试验代码，不作为当前可用功能 |
| `publish-version-info.yml`、`beta-pack.yml` | 两个旧工作流均限制 `github.repository == 'lyswhut/lx-music-mobile'`，在当前仓库不会执行 | 记录为无效的上游自动化；当前正式发布使用 `release.yml` |

依赖扫描还报出 2 个运行依赖和 10 个开发依赖候选。其中 `@craftzdog/react-native-buffer` 实际由 `metro.config.js` 把 `buffer` 别名映射到该包，**应保留**；ESLint/Babel/Metro 依赖也需按配置和构建链判断。`iconv-lite` 未查到项目直接调用，适合后续单独从依赖与锁文件中移除并构建验证。

`publish/index.js` 直接使用未声明的 `chalk`，当前依赖树中即使碰巧提供它，也不能视为稳定的直接依赖。这个旧 `npm run publish` 实际只更新版本说明文件，不等同于 Android Release 发布；应与正式发布流程一起单独整理。

## 功能存在，但入口缺失或实现不完整

| 功能 | 实际状态 | 处理／建议 |
| --- | --- | --- |
| 搜索歌单 | 完整搜索链存在，缺类型选择按钮 | 已恢复入口 |
| 切换歌曲／歌单搜索平台 | 平台列表和后端存在，缺可操作的选择器 | 已恢复入口并过滤不支持的平台 |
| 编辑并保存歌词 | `saveEditedLyric`、`clearEditedLyric` 存在，`getPlayerLyric` 会读取编辑副本；没有编辑或重置 UI | 属于后端可存储但没有编辑器的能力，保留并记录；不能只增加一个空按钮 |
| 自动更新收藏歌单 | `setListAutoUpdate` 只保存开关；没有设置入口，也没有按该开关执行的调度链 | 属于未完成能力，不能宣称自动同步已可用；现有手动同步仍可从歌单菜单使用 |
| 独立修改桌面歌词未播放颜色 | 原生与配置均支持，但当前调色板传入的第一个颜色参数为 `null`，只修改已播放颜色和阴影 | 没有独立颜色控件，列为待补入口 |
| 设置／全部数据备份 | 界面仅留被注释的按钮；没有对应 `importAndExportData` 实现，空的 `All.js` 也不是功能 | 属于未实现，不应算作已完成但藏起来的功能；目前可用的是列表备份 |
| 旧歌词滚动参考线的显示开关 | 只在未接入的旧 `SettingPopup` 和旧歌词页中读写；新播放器没有这套参考线 | 属于旧页面专用能力；应先确定新交互，再迁移或移除整套旧代码 |

已确认有入口、应继续保留的功能包括：音乐库下载记录与最近播放、歌单菜单导入本地音乐／导入导出／排序／去重／手动同步、播放菜单音质／音量／倍速／睡眠定时／排版／特效，以及设置中的桌面歌词和检查更新。桌面歌词窗口位置由拖动手势保存，不需要再加一个位置按钮。
